企业园区网架构设计——从三层架构到 Spine-Leaf

企业园区网是所有业务的承载基础，架构设计得好不好，直接影响后续十几年的运维成本和业务扩展能力。这篇文章从传统三层架构讲起，分析它的问题，再讲到现在主流的 Spine-Leaf + VXLAN/EVPN 架构，最后聊聊实际设计中的取舍。

一、传统三层架构

经典的园区网三层架构：接入层、汇聚层、核心层。

各层职责

接入层（Access）：

  • 直接连接终端设备（PC、IP电话、AP、摄像头、打印机）
  • PoE 供电（给 AP、IP 电话、摄像头供电）
  • 端口安全（802.1X、MAC 绑定、端口隔离）
  • VLAN 划分（接入端口通常是 Access 口，属于某个 VLAN）
  • STP 边缘端口（PortFast / Edge Port）

汇聚层（Aggregation/Distribution）：

  • 接入层的网关（VLAN 接口/SVI 配置在汇聚层）
  • 策略控制（ACL、QoS、策略路由）
  • 安全边界（防火墙、入侵检测通常挂在汇聚层）
  • 三层路由（汇聚层以上跑 OSPF/BGP，以下是二层）
  • 冗余设计（汇聚层通常双机，用 VRRP/HSRP 做网关冗余）

核心层（Core）：

  • 高速转发，不做策略（策略尽量在汇聚层做，核心只负责快速交换）
  • 连接各个汇聚块、数据中心、出口
  • 高带宽、低延迟（通常用万兆/四万兆链路）
  • 全互联拓扑（核心层设备之间 full-mesh 或环形）

三层架构的问题

  1. STP 阻塞链路，带宽利用率低
    汇聚到接入通常双上联，但 STP 会阻塞其中一条，实际可用带宽只有一条。50% 的链路在闲着。

  2. 收敛慢
    STP 收敛要 30-50 秒（即使开了 RSTP 也要几秒），链路故障时业务中断时间长。

  3. 东西向流量瓶颈
    服务器虚拟化之后，虚拟机之间的流量（东西向）暴增。传统架构里，同一汇聚块下的服务器之间流量要经过汇聚层转发，不同汇聚块之间要经过核心层，延迟高、容易拥塞。

  4. VLAN 数量限制
    传统 VLAN 只有 4094 个，大规模园区（特别是多租户场景）不够用。

  5. 虚拟机迁移受限
    VM 迁移要求二层网络连通，传统架构里二层域被限制在一个汇聚块下，VM 不能跨汇聚块迁移。

二、二层架构的演进——堆叠和 M-LAG

为了解决 STP 的问题，业界先做了一些改良：

2.1 设备堆叠（Stacking）

把多台物理交换机虚拟成一台逻辑交换机，堆叠成员之间用专用堆叠线缆连接。

  • 优点：管理简单（一台设备的管理面），跨设备链路聚合（EtherChannel），不需要 STP
  • 缺点：厂商私有协议（华为 iStack、华三 IRF、思科 VSS），不能跨厂商混合堆叠；控制面集中，主设备故障时整堆叠重启；升级需要整堆叠重启

2.2 M-LAG（Multi-Chassis Link Aggregation）

两台交换机组成 M-LAG 对，对下游设备表现为一台交换机，下游可以跨两台设备做链路聚合。但两台交换机的控制面是独立的，通过 M-LAG 协议同步状态。

  • 优点：控制面独立，单台故障不影响另一台；可以独立升级（ISSU）；比堆叠更可靠
  • 缺点：配置复杂，需要同步的状态多（MAC、ARP、STP）；厂商私有（华为 M-LAG、华三 DRNI、思科 vPC）；仍然是二层架构，VLAN 数量限制还在

三、Spine-Leaf 架构

Spine-Leaf（也叫 CLOS 架构）最早用在数据中心，现在也开始用在大型园区网的核心和汇聚部分。

核心特点

  1. 全互联：每个 Leaf 都和每个 Spine 相连，没有阻塞链路，所有链路都在转发
  2. 等价路由（ECMP）：Leaf 到 Leaf 之间有 N 条等价路径（N = Spine 数量），流量自动负载分担
  3. 三层到边缘：Leaf 和 Spine 之间跑三层路由（OSPF/BGP），没有 STP，没有二层环路
  4. 水平扩展：带宽不够加 Spine，端口不够加 Leaf，不需要替换核心设备

Spine-Leaf 为什么需要 VXLAN

Spine-Leaf 本身是三层架构，但园区网里有大量二层需求（VM 迁移、同一 VLAN 跨 Leaf）。纯三层架构下，不同 Leaf 下的同一 VLAN 是不通的。

解决方案：在三层网络上用 VXLAN 构建 Overlay 二层网络。

  • Underlay：Spine-Leaf 三层网络，跑 OSPF/BGP，负责 IP 连通
  • Overlay：VXLAN 隧道，在 Leaf 之间建立，把二层帧封装在 UDP 里传输
  • 控制面：EVPN（Ethernet VPN），用 BGP 传递 MAC 地址和 ARP 信息，替代传统的泛洪学习

VXLAN 报文封装

VXLAN 用 24 位 VNI 代替 12 位 VLAN ID，支持 1600 万个二层网络，彻底解决 VLAN 数量限制。

EVPN 控制面

传统 VXLAN 用数据面学习 MAC（泛洪），效率低。EVPN 用 BGP 作为控制面，Leaf 之间通过 BGP 更新消息交换 MAC 地址：

  • Type 2 路由：MAC/IP 通告（Leaf 学到本地 MAC 后，通过 BGP 告诉其他 Leaf）
  • Type 3 路由：Inclusive Multicast（用于 BUM 流量转发，替代泛洪）
  • Type 5 路由：IP 前缀通告（用于三层 VXLAN，跨 VNI 路由）

EVPN 的优势：

  • 不需要泛洪学习 MAC，减少广播流量
  • 支持 ARP 抑制（Leaf 本地代理 ARP，减少广播）
  • 支持 VM 迁移时的 MAC 移动检测
  • 统一的二层和三层控制面

四、实际设计中的取舍

4.1 中小园区（500人以下）

不需要 Spine-Leaf，传统三层架构 + M-LAG 就够了：

  • 核心：2台核心交换机做 M-LAG
  • 接入：每楼层1-2台接入交换机，双上联到核心
  • 网关：在核心上做 SVI
  • 路由：核心到出口跑静态或 OSPF

简单、可靠、运维成本低。

4.2 中大型园区（500-5000人）

核心用 Spine-Leaf，接入层保留传统架构：

  • Spine：2-4台高速交换机
  • Leaf：每楼层/每区域1-2台，作为汇聚+接入
  • VXLAN/EVPN：在 Leaf 之间构建 Overlay，支持跨区域二层
  • 无线：AC + AP，AP 二层注册到 AC

4.3 超大型园区/多园区互联

  • 每个园区独立的 Spine-Leaf
  • 园区之间用 SD-WAN 或 MPLS VPN 互联
  • 统一的 EVPN 控制面（跨园区的 MAC/IP 同步）
  • 身份驱动的网络（ISE/AAA，按用户身份分配 VLAN 和策略）

4.4 无线网络的融合

现代园区网里无线流量占比越来越高（很多公司 70%+ 流量是无线），设计时要考虑：

  • CAPWAP 隧道：AP 和 AC 之间用 CAPWAP 封装，AP 只需要二层到 AC 就行
  • 本地转发 vs 集中转发：本地转发（数据在 AP 本地解封装）性能好，集中转发（所有数据回 AC）策略统一但 AC 是瓶颈
  • Wi-Fi 6/7：高密度场景需要考虑 AP 部署密度、信道规划、漫游
  • 802.1X：无线和有线统一认证，按身份分配 VLAN

五、网络设计的通用原则

  1. 分层设计：每层职责清晰，不要把接入、网关、策略、安全全堆在一台设备上
  2. 冗余设计：关键节点双机、链路双上联、电源双路、控制面和数据面分离
  3. 模块化：按区域/楼层/业务划分模块，模块之间通过标准接口连接，方便扩展和故障隔离
  4. 可观测性：设计阶段就要考虑监控（NetFlow/sFlow、SNMP、Syslog、链路状态），没有监控的网络就是黑盒
  5. 安全域划分：办公区、服务器区、DMZ、管理区、生产区，不同安全域之间用防火墙隔离，不要全通
  6. 地址规划：IP 地址按区域和业务规划，预留扩展空间，不要随便用 192.168.1.0/24 这种到处都是的网段

六、总结

企业园区网架构从传统三层架构，到堆叠/M-LAG 改良，再到 Spine-Leaf + VXLAN/EVPN，核心驱动力是：

  1. 带宽需求增长（虚拟化、云计算、无线）
  2. 东西向流量增加（服务器之间、微服务之间）
  3. 灵活性需求（VM 迁移、弹性扩展、多租户）

但不是所有场景都需要最先进的架构。中小园区用传统三层 + M-LAG 就很好，运维简单、成本低。Spine-Leaf + VXLAN 适合大规模、高带宽、有虚拟化和多租户需求的场景。架构选型的关键是匹配业务需求，而不是追新技术。
