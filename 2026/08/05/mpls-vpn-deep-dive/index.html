MPLS VPN 深度解析——L3VPN、L2VPN 与运营商骨干网

MPLS（多协议标签交换）曾经是运营商骨干网的绝对主流，现在虽然在数据中心被 VXLAN 替代，但在运营商 WAN 和企业专线场景里仍然无处不在。企业用的 MPLS 专线、SD-WAN 的 Underlay、VPN 服务，底层很多都是 MPLS。这篇文章从 MPLS 基础讲到 L3VPN 和 L2VPN 的实现原理。

一、MPLS 基础

1.1 什么是 MPLS

MPLS 的核心思想：在报文进入网络时给它打一个标签（Label），后续转发只看标签，不看 IP 头。

传统 IP 转发是”逐跳查路由表”，每台路由器都要查最长前缀匹配，性能受路由表规模影响。MPLS 把”路由查找”变成”标签交换”，标签是固定长度的整数，查标签表比查路由表快得多。

MPLS 介于二层和三层之间，所以叫”2.5 层协议”。

1.2 MPLS 报文格式

标签栈放在二层头和三层头之间：

单个标签 4 字节（32 位）：

  • Label：20 位，标签值（0-15 保留，16 以上可用）
  • TC：3 位，流量类别（原来叫 EXP，用于 QoS）
  • S：1 位，栈底标记（1 表示这是标签栈的最后一个标签）
  • TTL：8 位，生存时间（和 IP TTL 一样，每跳减 1，防环路）

标签可以嵌套（标签栈），最外层标签先处理，这是 MPLS VPN 的基础。

1.3 MPLS 网络角色

核心设计思想：P 设备只负责标签转发，不需要知道任何 VPN 信息。所有 VPN 相关的处理都在 PE 上完成，P 设备只看最外层标签做转发。这样 P 设备可以很简单、很快，VPN 的复杂度集中在 PE 上。

1.4 标签分发协议（LDP）

LDP（Label Distribution Protocol）用来在 MPLS 域内分发标签，建立 LSP（标签交换路径）。

LDP 的工作方式：

  1. 每台设备为自己的环回口地址（Loopback）分配一个标签
  2. 通过 LDP 把标签告诉邻居
  3. 邻居收到后，在自己的标签转发表（LFIB）里记录：”到 X 的标签是 Y，下一跳是 Z”
  4. 逐跳建立 LSP，从入口 PE 到出口 PE 形成一条标签交换路径

LDP 只负责为 IGP 路由（OSPF/IS-IS）分配标签，不负责 VPN 路由。VPN 路由的标签用 MP-BGP 分发。

二、MPLS L3VPN——最经典的 VPN 服务

MPLS L3VPN（RFC 4364，也叫 BGP/MPLS IP VPN）是运营商最常用的 VPN 服务，企业的 MPLS 专线基本都是这个。

2.1 核心概念

VRF（VPN Routing and Forwarding Instance）：
PE 上为每个 VPN 创建一个独立的路由表（VRF），不同 VPN 的路由完全隔离。一个物理 PE 可以有多个 VRF，每个 VRF 绑定一个或多个连接 CE 的接口。

RD（Route Distinguisher，路由区分符）：
不同 VPN 可能用相同的 IP 地址段（比如都用 10.0.0.0/8），为了区分，PE 把 VPN 路由变成 VPNv4 地址：RD + IPv4 地址。

RD 是 8 字节，格式通常是 ASN:NN 或 IP:NN，比如 65001:100。

VPNv4 地址 = RD(8B) + IPv4(4B) = 12 字节，全局唯一。

RT（Route Target，路由目标）：
RT 控制 VPN 路由的导入导出，决定哪些 PE 接收哪些 VPN 路由。

  • Export RT：PE 导出 VPN 路由时，给路由打上 Export RT 标记
  • Import RT：PE 的 VRF 配置 Import RT，只导入匹配的 VPN 路由

RT 也是 8 字节，格式和 RD 类似。一个 VRF 可以配置多个 Export RT 和 Import RT，实现 Hub-Spoke、全互联等拓扑。

2.2 L3VPN 控制面——路由怎么传播

以 VPN-A 为例，CE-A1 把路由发给 PE1：

详细过程：

  1. CE 到 PE：CE-A1 和 PE1 之间跑路由协议（EBGP、OSPF、EIGRP、静态都可以），CE-A1 把自己的内网路由（比如 10.1.0.0/24）发给 PE1

  2. PE 处理：PE1 把路由收到 VRF-A 的路由表里，然后：

    • 给路由加上 RD，变成 VPNv4 路由：RD=65001:100 + 10.1.0.0/24
    • 给路由打上 Export RT（比如 65001:100）
    • 给路由分配一个 VPN 标签（MP-BGP 标签）
    • 通过 MP-BGP（多协议 BGP，地址族 VPNv4）发给 PE2

  3. PE 之间：MP-BGP 更新消息在 PE 之间传递，经过 P 设备时，P 设备不解析 VPNv4 路由（P 不需要知道 VPN 信息），只负责转发 BGP 报文

  4. PE2 处理：PE2 收到 VPNv4 路由后：

    • 检查路由的 RT 是否匹配 VRF-A 的 Import RT
    • 匹配则剥离 RD，把 IPv4 路由（10.1.0.0/24）导入 VRF-A 的路由表
    • 记录 VPN 标签和下一跳（PE1 的环回口地址）

  5. PE 到 CE：PE2 通过和 CE-A2 之间的路由协议，把路由发给 CE-A2

2.3 L3VPN 数据面——报文怎么转发

CE-A1 发一个报文到 CE-A2（源 10.1.0.1，目的 10.2.0.1）：

  1. CE-A1 → PE1：普通 IP 报文，CE-A1 查路由表，下一跳是 PE1 的接口地址

  2. PE1 处理（入站 PE）：

    • 报文从绑定 VRF-A 的接口进入，查 VRF-A 的路由表
    • 找到 10.2.0.0/24 的路由，下一跳是 PE2 的环回口，关联一个 VPN 标签（L2）
    • 查公网路由表，到 PE2 环回口的 LSP 出标签是 L1（通过 LDP 学到）
    • 压入两层标签：外层 L1（到 PE2 的 LSP 标签），内层 L2（VPN 标签）
    • 报文变成：IP头 | 标签L1 | 标签L2(S=0) | 原始IP报文

  3. P 设备转发：

    • P 收到报文，只看最外层标签 L1
    • 查 LFIB（标签转发信息库），L1 的出标签是 L1’，下一跳是下一个 P
    • 交换标签：把 L1 换成 L1’，TTL 减 1
    • 内层标签 L2 完全不碰，P 不知道也不关心里面是什么
    • 逐跳转发，直到到达 PE2

  4. PE2 处理（出站 PE）：

    • PE2 收到报文，外层标签 L1’ 的 TTL 到 0 或标签是 PHP（倒数第二跳弹出）标签，PE2 弹出外层标签
    • 看内层标签 L2，查 VPN 标签转发表，L2 对应 VRF-A 和出接口
    • 弹出内层标签，恢复原始 IP 报文
    • 查 VRF-A 的路由表，从绑定 VRF-A 的接口发给 CE-A2

  5. PE2 → CE-A2：普通 IP 报文

关键点：P 设备只做标签交换，完全不感知 VPN。VPN 的所有复杂性都在 PE 上，P 设备可以很简单、很快。这就是 MPLS VPN 能大规模扩展的原因——P 设备数量可以很多，但不需要维护 VPN 状态。

2.4 PHP（Penultimate Hop Popping，倒数第二跳弹出）

PHP 是 MPLS 的一个优化机制：在到达出站 PE 的前一跳（P 设备），就把外层标签弹掉，这样出站 PE 收到的是只有内层标签的报文，不需要再查一次外层标签表，减少 PE 的处理负担。

实现方式：出站 PE 为自己的环回口分配一个特殊标签 3（Implicit Null），通过 LDP 告诉邻居。P 设备看到出标签是 3，就不压入标签，直接弹出。

2.5 L3VPN 的拓扑类型

通过 RT 的不同组合，可以实现不同的 VPN 拓扑：

全互联（Full Mesh）：

  • 每个 PE 的 VRF 都 Export 和 Import 相同的 RT
  • 所有站点之间互通

Hub-Spoke（中心-分支）：

  • Hub 站点的 VRF：Export RT=Hub，Import RT=Spoke
  • Spoke 站点的 VRF：Export RT=Spoke，Import RT=Hub
  • Spoke 之间不能直接通信，必须经过 Hub（Hub 可以做安全检查、流量审计）

Extranet（外联网）：

  • 两个不同的 VPN 之间部分互通
  • 通过在一个 VRF 里 Import 另一个 VPN 的 RT 实现
  • 可以精确控制哪些网段互通

三、MPLS L2VPN——二层透传服务

L3VPN 是三层路由服务，PE 参与客户的路由。L2VPN 是二层透传服务，PE 不参与客户路由，只把客户的二层帧透传到对端，客户感觉就像用一根网线把两个站点连起来。

3.1 VPWS（Virtual Private Wire Service，虚拟专线服务）

VPWS 是点到点的二层透传，相当于一条虚拟的二层专线。

  • PE1 把从 CE1 收到的二层帧（以太网帧）封装在 MPLS 里，通过 LSP 发给 PE2
  • PE2 剥掉 MPLS 头，把原始二层帧发给 CE2
  • 对 CE 来说，就像直接用网线连在一起，同一个 VLAN、同一个网段
  • 点到点，一个 VPWS 只能连两个站点

VPWS 用的信令协议：

  • LDP（Martini 模式，RFC 4906）：用 LDP 分发 VC 标签（二层电路标签）
  • BGP（Kompella 模式）：用 BGP 分发 VC 标签，支持自动发现

3.2 VPLS（Virtual Private LAN Service，虚拟专用局域网服务）

VPLS 是点到多点的二层透传，相当于把多个站点连在一个虚拟交换机上，所有站点在同一个广播域里。

VPLS 的核心：PE 之间全互联的伪线（PW），每个 PE 模拟一个虚拟交换机的端口。

工作原理：

  1. 每个 PE 为 VPLS 实例维护一个 MAC 地址表（和普通交换机一样）
  2. PE 之间用全互联的 PW（伪线，基于 MPLS 的点到点隧道）连接
  3. 单播帧：PE 查 MAC 表，从对应的 PW 或本地接口转发
  4. 广播/组播/未知单播（BUM 流量）：从所有其他 PW 和本地接口泛洪（水平分割：从 PW 收到的帧不再从其他 PW 发出，避免环路）
  5. MAC 学习：和普通交换机一样，从源 MAC 学习端口

VPLS 的问题：

  • 全互联 PW 的 N^2 问题：N 个 PE 需要 N*(N-1)/2 条 PW，规模大了不可扩展
  • BUM 流量泛洪：广播帧要复制到所有 PE，带宽浪费
  • MAC 表规模：所有站点的 MAC 都要学到每个 PE，MAC 表可能很大

为了解决 VPLS 的扩展问题，后来有了：

  • H-VPLS（分层 VPLS）：引入汇聚层，减少全互联
  • EVPN（Ethernet VPN）：用 BGP 做控制面，替代数据面的 MAC 学习和泛洪，是现在的主流

3.3 EVPN（Ethernet VPN）

EVPN 是下一代二层 VPN 技术，用 BGP 作为控制面，解决了 VPLS 的扩展问题。

EVPN 的核心思想（和 VXLAN EVPN 一样）：

  • 控制面学习 MAC：PE 通过 BGP 通告 MAC 地址（Type 2 路由），不需要数据面泛洪学习
  • ARP 抑制：PE 本地代理 ARP，减少广播
  • BUM 流量用 Inclusive Multicast（Type 3 路由）：用组播或 Ingress Replication 转发 BUM，不需要全互联泛洪
  • 支持多归接入（Multi-homing）：一个 CE 可以双归到两个 PE，用 ES（Ethernet Segment）实现负载分担和冗余

EVPN 可以承载多种数据面：

  • EVPN over MPLS：传统运营商网络
  • EVPN over VXLAN：数据中心网络（现在最主流）
  • EVPN over SRv6：下一代运营商网络

四、MPLS 的演进——从 MPLS 到 SR/SRv6

传统 MPLS 用 LDP 分发标签、RSVP-TE 建立流量工程隧道，协议复杂、运维困难。现在运营商在向 Segment Routing（段路由） 演进。

4.1 SR-MPLS

Segment Routing 的核心思想：源节点在报文头里压入一个标签栈（段列表），指定报文要经过的路径，中间节点只做标签交换，不需要维护路径状态。

  • 不需要 LDP 和 RSVP-TE，标签由 IGP（OSPF/IS-IS）扩展分发
  • 源路由，路径在头节点指定，中间节点无状态
  • 可以灵活实现流量工程、快速重路由（FRR）
  • 和 MPLS 数据面兼容，只是控制面变了

4.2 SRv6

SRv6 把 Segment Routing 的思想用在 IPv6 上，用 IPv6 扩展头（SRH，Segment Routing Header）携带段列表，段列表是 IPv6 地址列表。

  • 不需要 MPLS 标签，纯 IPv6 转发
  • 用 IPv6 地址作为段标识，地址空间巨大
  • 可以和传统 IPv6 网络互通
  • 是运营商 5G 承载网和下一代骨干网的主流方向

五、企业视角：MPLS 专线 vs SD-WAN

企业用 WAN 连接多个站点，传统方案是 MPLS 专线，现在很多企业在考虑 SD-WAN。两者不是替代关系，而是互补：

维度 MPLS 专线 SD-WAN
带宽成本 高（运营商垄断，每Mbps贵） 低（用互联网宽带，便宜）
SLA 保障 高（运营商承诺延迟、丢包、可用率） 中（依赖互联网质量，靠智能选路和丢包恢复弥补）
开通速度 慢（几周到几个月，需要运营商施工） 快（几天，CPE 插电就能用）
灵活性 低（加带宽要找运营商，改拓扑要重新规划） 高（软件定义，策略随时改，带宽弹性扩展）
安全性 中（运营商网络隔离，但不是加密） 高（IPSec 加密，零信任集成）
云应用访问 差（流量回总部再出去，延迟高） 好（本地突破，直接访问云应用）
适用场景 关键业务、对 SLA 要求极高 一般业务、云应用、多分支

现在的主流趋势是 SD-WAN + MPLS 混合组网：

  • 关键业务（交易、语音）走 MPLS 专线，保障 SLA
  • 一般业务（网页、邮件、云应用）走互联网，降低成本
  • SD-WAN 做智能选路和统一管理，MPLS 作为 Underlay 的一条链路

六、总结

MPLS 技术体系的核心：

  1. 标签交换：用标签代替 IP 前缀查找，转发更快
  2. PE/P 分离：VPN 复杂性集中在 PE，P 只做简单标签交换，可大规模扩展
  3. L3VPN：用 VRF + RD + RT + MP-BGP 实现三层 VPN 路由隔离
  4. L2VPN：用伪线实现二层透传，VPWS 点到点，VPLS/EVPN 点到多点
  5. 数据面封装：两层标签（外层 LSP 标签 + 内层 VPN/VC 标签）

理解了 MPLS VPN，再看 SD-WAN、VXLAN、SRv6 这些新技术，会发现很多思想是相通的——都是 Underlay + Overlay 的分离，都是控制面和数据面的分离，都是用隧道封装实现逻辑网络和物理网络的解耦。
