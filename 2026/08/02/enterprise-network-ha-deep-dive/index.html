企业网络高可用技术全解——VRRP、链路聚合、堆叠与 M-LAG

网络高可用是企业网设计的核心指标，目标是单点故障不影响业务。这篇文章把企业网里常用的高可用技术从原理到配置全过一遍：网关冗余（VRRP/HSRP）、链路冗余（LACP/堆叠/M-LAG）、故障快速检测（BFD）。

一、高可用的基本概念

1.1 可用性指标

可用性用”几个9”来衡量：

可用性 年停机时间 适用场景
99% 3.65 天 非关键业务
99.9% 8.76 小时 一般企业
99.99% 52.6 分钟 关键业务
99.999% 5.26 分钟 电信级/金融

要达到 99.99% 以上，必须做到：

  • 所有关键节点双机冗余
  • 所有链路双上联
  • 故障切换时间 < 1 秒（亚秒级）
  • 无单点故障

1.2 高可用的层次

网络层高可用解决的是：某台设备或某条链路故障时，流量能自动切换到备份路径，业务不中断。

二、网关冗余——VRRP / HSRP / GLBP

终端的默认网关通常是一个 IP 地址，如果网关设备挂了，终端就断网了。网关冗余协议解决的是”多台设备虚拟成一个网关”的问题。

2.1 VRRP（Virtual Router Redundancy Protocol）

VRRP 是 IETF 标准（RFC 5798），业界主流。

原理：多台路由器组成一个 VRRP 组，虚拟出一个虚拟路由器（Virtual Router），有虚拟 IP 和虚拟 MAC。终端把默认网关设为虚拟 IP。

工作机制：

  • Master 负责转发流量，响应 ARP 请求（用虚拟 MAC）
  • Backup 监听 Master 的状态，不转发流量
  • Master 周期性发送 VRRP 通告（默认 1 秒，组播 224.0.0.18）
  • Backup 连续 3 个通告周期（默认 3 秒）没收到 Master 的通告，就认为 Master 故障，抢占成为新的 Master
  • 新 Master 发送免费 ARP（Gratuitous ARP），通知交换机更新 MAC 地址表

优先级和抢占：

  • 优先级 1-254，默认 100，优先级高的成为 Master
  • 优先级 255 保留给虚拟 IP 拥有者（接口 IP = 虚拟 IP 的设备）
  • 抢占模式（默认开启）：高优先级的 Backup 发现 Master 优先级比自己低，会抢占成为 Master
  • 可以配置抢占延迟（避免网络不稳定时频繁切换）

接口跟踪（Interface Tracking）：
Master 的上行接口故障时，虽然 Master 本身还活着，但流量已经出不去了。配置接口跟踪后，上行接口故障时 Master 自动降低优先级，让 Backup 抢占。

2.2 HSRP（Hot Standby Router Protocol）

HSRP 是思科私有协议，原理和 VRRP 几乎一样，细节略有不同：

  • HSRP 有 Active/Standby 两种角色（VRRP 是 Master/Backup）
  • HSRP 默认 Hello 时间 3 秒，Hold 时间 10 秒（VRRP 默认 1 秒/3 秒）
  • HSRP 支持 MD5 认证（VRRPv3 也支持）
  • 虚拟 MAC 格式不同：HSRP 是 0000.0c07.acxx，VRRP 是 0000.5e00.01xx

现在思科设备也支持 VRRP，新项目推荐用 VRRP（标准协议，多厂商兼容）。

2.3 GLBP（Gateway Load Balancing Protocol）

VRRP/HSRP 同一时间只有 Master/Active 转发流量，Backup 闲着，带宽浪费。GLBP（思科私有）可以让多台设备同时转发流量，实现负载均衡。

GLBP 有一个 AVG（Active Virtual Gateway）负责响应 ARP，把不同的虚拟 MAC 分给不同的终端，终端的流量就分散到不同的网关上。

GLBP 用得不多，因为：

  • 思科私有，多厂商环境不能用
  • 负载均衡粒度粗（按终端分，不是按流量分）
  • 现在更多用 M-LAG 或等价路由做负载均衡

2.4 VRRP 的问题和优化

问题 1：切换时间长
默认 VRRP 切换要 3 秒（3 个通告周期），对关键业务来说太长了。

优化：

  • 调小通告间隔（比如 100ms），但会增加 CPU 开销
  • 用 BFD 联动 VRRP（BFD 检测故障 < 100ms，检测到后立即触发 VRRP 切换，不需要等通告超时）

问题 2：上行链路故障检测慢
接口跟踪只能检测直连接口故障，如果上行中间链路断了（不是直连接口），接口还是 Up 的，检测不到。

优化：

  • 用 BFD 检测上行链路（BFD 可以检测非直连链路）
  • 用 IP SLA + Track 检测端到端连通性

问题 3：流量不对称
Master 故障切换到 Backup 后，回程流量可能还走旧 Master（如果路由还没收敛），导致状态防火墙丢包。

优化：

  • 调整路由协议的收敛时间
  • 状态防火墙做会话同步

三、链路冗余——LACP / 堆叠 / M-LAG

设备之间的单条链路是单点故障，链路冗余解决的是”一条链路断了，另一条自动接管”的问题。

3.1 静态聚合 vs LACP 动态聚合

把多条物理链路捆绑成一条逻辑链路（Eth-Trunk / Port-Channel），既增加带宽又提供冗余。

静态聚合：手动把接口加入聚合组，不跑协议。配置简单，但对端如果没配好（比如只配了一端），会产生环路或丢包。

LACP（Link Aggregation Control Protocol，IEEE 802.3ad）：动态聚合协议，两端通过 LACPDU 协商聚合，自动检测配置错误和链路故障。

LACP 关键参数：

  • 模式：Active（主动发送 LACPDU）/ Passive（只响应不主动发）。两端至少有一端是 Active 才能协商成功
  • 系统优先级：决定哪端是主动端，主动端决定哪些接口是活动接口
  • 接口优先级：在活动接口数达到上限时，优先级高的接口优先成为活动接口
  • 最大活动接口数：聚合组里最多有多少条链路同时转发（其他作为备份）
  • 超时时间：Fast（1 秒超时，每秒发 1 个 LACPDU）/ Slow（30 秒超时，每 30 秒发 1 个）。Fast 模式故障检测更快

负载分担方式：
聚合组里的流量按哈希算法分配到不同物理链路，哈希因子可以选：

  • 源 MAC（适合二层流量）
  • 目的 MAC
  • 源 IP（适合三层流量）
  • 目的 IP
  • 源端口 + 目的端口（适合四层流量，最均衡）
  • 组合：源IP+目的IP+源端口+目的端口

选择原则：流量的特征越丰富，哈希越均衡。如果只有少数几个大流量（比如服务器之间的备份），用五元组哈希；如果是大量小流量（终端上网），用源IP+目的IP就够了。

注意：哈希是 per-flow（按流），不是 per-packet（按包）。同一条流（五元组相同）始终走同一条物理链路，保证报文不乱序。所以聚合组的带宽不是简单的 N 倍，而是”最大单条流带宽 = 单条物理链路带宽，总带宽 = N 条物理链路带宽之和”。

3.2 设备堆叠（Stacking / iStack / IRF / VSS）

链路聚合只能解决链路冗余，不能解决设备冗余。堆叠把多台物理交换机虚拟成一台逻辑交换机，从根本上解决设备单点故障。

原理：

  • 堆叠成员之间用专用堆叠线缆（或普通以太网口做堆叠口）连接
  • 主设备（Master）负责控制面（管理、路由、协议），从设备（Slave）转发数据
  • 控制面集中，数据面分布式
  • 跨设备链路聚合：下游设备可以把链路分别接到堆叠的不同成员上，组成聚合组，单台成员故障不影响

堆叠的优点：

  • 管理简单：一台设备的管理面，一个 IP 管理所有成员
  • 跨设备链路聚合：真正的无环二层，不需要 STP
  • 故障切换快：成员故障时，堆叠系统快速检测，流量切换到其他成员
  • 配置同步：主设备配置自动同步到从设备

堆叠的缺点：

  • 厂商私有：华为 iStack、华三 IRF、思科 VSS、Arista MLAG，不能跨厂商堆叠
  • 控制面集中：主设备故障时，整堆叠重启（虽然有 NSF/NSR 等不中断转发技术，但控制面还是会断）
  • 升级困难：堆叠升级要整组重启（ISSU 可以逐成员升级，但复杂且有风险）
  • 脑裂风险：堆叠线缆断了之后，两边都认为自己是 Master，产生双主，导致 IP/MAC 冲突。需要配置双主检测（DAD，通过管理口或业务口发送检测报文）
  • 爆炸半径大：堆叠系统的一个 bug 可能影响所有成员

堆叠 vs 独立设备 + M-LAG：

  • 堆叠适合接入层（设备数量多、管理成本高、对控制面中断不敏感）
  • M-LAG 适合核心/汇聚层（对可靠性要求高、需要独立升级、控制面不能断）

3.3 M-LAG（Multi-Chassis Link Aggregation）

M-LAG 是堆叠的改进版，两台设备组成 M-LAG 对，对下游表现为一台设备（可以跨设备做链路聚合），但控制面是独立的。

M-LAG 的关键组件：

  • Peer-link：M-LAG 对之间的直连链路（通常是聚合组，多条链路），用于同步 MAC 地址表、ARP 表、M-LAG 成员状态，以及转发跨设备流量
  • Keepalive 链路：心跳链路（可以用管理口或业务口），用于检测对端是否存活，防止 peer-link 故障时产生脑裂
  • M-LAG 成员接口：两端设备上和下游设备连接的接口，组成 M-LAG 聚合组
  • DFS Group（Dynamic Fabric Service）：M-LAG 的域标识，两端必须一致

M-LAG 的工作机制：

  1. 两台设备通过 peer-link 同步 MAC、ARP、STP 状态
  2. 对下游设备来说，两台设备是一台交换机（桥 MAC 相同），下游可以做跨设备链路聚合
  3. 单播流量：本地优先（从 SW1 进来的流量优先从 SW1 出去，不需要经过 peer-link）
  4. 广播/未知单播：通过 peer-link 同步到对端
  5. 单台设备故障：另一台接管所有 M-LAG 成员接口的流量，通过 peer-link 转发
  6. peer-link 故障：通过 keepalive 检测，备设备关闭自己的 M-LAG 成员接口，防止双主

M-LAG 相比堆叠的优势：

  • 控制面独立：单台设备故障不影响另一台的控制面，路由协议不中断
  • 独立升级：可以逐台升级（ISSU），业务不中断
  • 无堆叠线缆：用普通以太网口做 peer-link，距离不受限（堆叠线缆通常很短）
  • 爆炸半径小：一台设备的 bug 只影响自己

M-LAG 的缺点：

  • 配置复杂（比堆叠多很多配置项）
  • 厂商私有（华为 M-LAG、华三 DRNI、思科 vPC、Arista MLAG）
  • peer-link 是关键路径，peer-link 故障处理复杂
  • 需要维护两台设备的配置一致性（虽然有自动同步，但还是要注意）

3.4 技术选型建议

场景 推荐方案
接入层，大量交换机，管理优先 堆叠（iStack/IRF）
汇聚/核心层，可靠性优先 M-LAG（MLAG/vPC/DRNI）
服务器双网卡绑定 M-LAG（跨设备链路聚合）
设备之间互联 LACP 动态聚合
网关冗余 VRRP + BFD
数据中心大二层 VXLAN + EVPN（不用堆叠/M-LAG）

四、故障快速检测——BFD

传统路由协议的故障检测靠 Hello 超时（OSPF 默认 40 秒，IS-IS 默认 30 秒），太慢了。BFD（Bidirectional Forwarding Detection，双向转发检测）专门做快速故障检测，能做到亚秒级（最小 3.3ms）。

4.1 BFD 原理

BFD 在两台设备之间建立 BFD 会话，周期性发送 BFD 控制报文，如果在检测时间内没收到对端的报文，就认为链路故障，通知上层协议（OSPF/BGP/VRRP/静态路由）快速切换。

BFD 是一个简单的”Hello 协议”，只负责检测，不负责路由计算。检测到故障后通知上层协议处理，所以 BFD 通常和 OSPF/BGP/VRRP/静态路由联动。

4.2 BFD 模式

  • 异步模式（Asynchronous）：双方周期性发送 BFD 报文，检测不到就认为故障。这是默认模式，最常用。
  • 需求模式（Demand）：不周期性发送报文，需要时才发（比如有数据要发时捎带检测）。适合链路带宽紧张的场景，用得少。
  • 回声模式（Echo）：一方发回声报文，对端不处理直接环回回来，发送方自己检测。回声模式可以检测对端的转发平面故障（控制面正常但转发面挂了的情况），通常和异步模式配合使用。

4.3 BFD 配置

配置后，OSPF 邻居的故障检测时间从默认 40 秒降到 300 毫秒。

4.4 BFD 的注意事项

  1. 间隔不能太小：BFD 报文间隔太小会增加 CPU 开销，设备性能不够时会导致 BFD 报文被延迟发送，误判故障。一般设备最小支持 3.3ms（高端设备），普通设备建议 100ms 以上。
  2. 检测倍数至少 3：小于 3 容易因为偶尔的报文丢失误判故障。
  3. BFD 和 STP 的冲突：BFD 检测到链路故障后立即通知路由切换，但 STP 还在收敛（STP 要 30 秒），可能导致临时环路。二层环境用 BFD 要注意 STP 的配合，或者用 RSTP/MSTP 加快收敛。
  4. BFD over LAG：聚合组里的 BFD 可以检测单条成员链路故障，也可以检测整个聚合组故障。注意 BFD 会话绑定的是聚合接口还是物理接口。
  5. BFD 多跳：BFD 可以检测非直连链路（多跳 BFD），用于检测端到端路径故障，通常和静态路由或 BGP 联动。

五、路由层高可用

除了网关和链路，路由层面也要做冗余：

5.1 等价路由（ECMP）

到同一目的地址有多条等价路由，设备自动做负载分担。一条链路故障时，路由协议快速收敛，流量切换到其他链路。

OSPF/IS-IS/BGP 都支持 ECMP，关键是要保证多条路径的 metric 相同。

5.2 路由快速收敛

  • OSPF：调小 Hello 间隔（1-5秒）、Dead 间隔（4倍Hello），开启 BFD 联动，开启 LSA 加速泛洪
  • BGP：开启 BFD 联动，调小 Keepalive/Hold 时间（但不要太小，BGP 是 TCP，太频繁会增加开销），开启 Add-Path（发送多条路径，快速切换）
  • 静态路由：用 IP SLA + Track + BFD 检测下一跳可达性，故障时自动切换浮动静态路由

5.3 不中断转发（NSF/NSR/GR）

设备主备引擎切换或堆叠主设备切换时，控制面会短暂中断，但数据面可以继续转发（转发表已经下发到硬件）。

  • GR（Graceful Restart，优雅重启）：重启设备通知邻居”我在重启，别删路由”，邻居保持转发，重启完成后重新建立邻居。需要邻居支持 GR Helper。
  • NSF（Non-Stop Forwarding，不中断转发）：思科的术语，和 GR 类似。
  • NSR（Non-Stop Routing，不中断路由）：主备引擎实时同步路由状态，切换时邻居完全感知不到，不需要邻居配合。比 GR 更高级，但对设备性能要求高。

六、高可用设计的最佳实践

  1. 消除单点故障：从物理层到应用层，每个环节都要双冗余。双电源、双引擎、双设备、双链路、双上联。
  2. 故障域隔离：不要把所有鸡蛋放一个篮子里。核心层和汇聚层分离，不同业务用不同 VRF/VLAN，一个故障域的问题不影响其他。
  3. 亚秒级切换：关键链路用 BFD 检测（< 300ms），网关用 VRRP + BFD，设备用 M-LAG/堆叠。
  4. 避免 STP 阻塞：能用链路聚合和 M-LAG 就不用 STP，STP 收敛慢（即使 RSTP 也要几秒），而且阻塞链路浪费带宽。
  5. 监控和演练：高可用不是配完就完事，要持续监控链路状态、设备健康、协议邻居。定期做故障演练（拔线、关机），验证切换是否符合预期。
  6. 文档化：每个冗余对、每条聚合组、每个 VRRP 组都要记录，故障时能快速定位。
  7. 不要过度设计：高可用是有成本的（设备、链路、运维复杂度），根据业务的可用性需求设计，不要为了”看起来高级”而过度冗余。接入层双上联就够了，不需要每台接入都做 M-LAG。

七、总结

企业网络高可用的技术栈：

层次 技术 作用
网关冗余 VRRP/HSRP + BFD 网关设备故障不中断
链路冗余 LACP 动态聚合 单条链路故障不中断
设备冗余 堆叠 / M-LAG 单台设备故障不中断
故障检测 BFD 亚秒级故障检测
路由冗余 ECMP + 快速收敛 路由层面多路径
控制面冗余 NSF/NSR/GR 设备切换不中断转发

理解了这些技术的原理和适用场景，在做网络设计时就能根据业务需求选择合适的高可用方案，而不是盲目堆设备。高可用的核心不是”用了多少高级技术”，而是”单点故障时业务能不能不中断”——一切设计都要围绕这个目标。
