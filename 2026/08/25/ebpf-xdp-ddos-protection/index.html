eBPF 实战——用 XDP 做线速 DDoS 防护

传统的 DDoS 防护要么靠硬件防火墙（贵），要么靠 iptables（慢，在内核协议栈深处处理）。eBPF + XDP 提供了第三种选择：在网卡驱动层、报文进入内核协议栈之前就把攻击包丢掉，性能接近硬件级。

这篇文章从 eBPF 原理讲到 XDP 实战，最后写一个能跑的 SYN Flood 防护程序。

一、eBPF 到底是什么

eBPF（extended Berkeley Packet Filter）是 Linux 内核里的一个虚拟机，可以让用户把一段小程序加载到内核里，在内核的特定钩子点（hook point）执行。

关键点：

  • 安全：eBPF 程序加载前会经过内核验证器（verifier）检查，不能有循环、不能越界访问、不能崩溃内核
  • 高效：程序编译成 BPF 字节码，内核 JIT 编译成本地机器码执行，几乎没有性能损耗
  • 可编程：不需要重新编译内核，不需要加载内核模块，用户态程序加载 eBPF 程序就能动态修改内核行为

eBPF 可以挂载的钩子点非常多：

  • 网络：XDP（网卡驱动层）、TC（流量控制层）、socket 层
  • 跟踪：kprobe、uprobe、tracepoint、perf event
  • 安全：LSM（Linux Security Module）
  • cgroup：在 cgroup 层级上做网络和资源控制

二、XDP 为什么快

XDP（eXpress Data Path）是 eBPF 在网络数据路径上最早、最经典的应用。它的钩子点在网卡驱动的收包路径上，报文刚从 DMA 缓冲区拿出来，还没进入内核协议栈，就可以被 XDP 程序处理。

性能差距有多大？官方测试数据：

  • iptables：单核约 1-2 Mpps（百万包每秒）
  • XDP：单核约 10-20 Mpps，支持多队列网卡横向扩展

原因很简单：XDP 处理时，报文还在驱动的 page buffer 里，不需要分配 sk_buff（这是内核网络栈里最重的操作之一），不需要经过 conntrack，不需要走 Netfilter 的一条条规则链。

三、XDP 程序的返回值

XDP 程序处理完一个报文后，必须返回一个动作，告诉内核接下来怎么办：

返回值 含义 性能
XDP_DROP 丢弃报文 最快，直接释放 page
XDP_PASS 上送协议栈，正常处理 正常路径
XDP_TX 从同一个网卡发回去 快，不需要进协议栈
XDP_REDIRECT 转发到另一个网卡或 CPU 快，用于负载均衡/路由
XDP_ABORTED 程序出错，丢弃 错误路径

做 DDoS 防护，核心就是在 XDP 程序里判断”这个包是不是攻击包”，是就返回 XDP_DROP，不是就返回 XDP_PASS。

四、实战：SYN Flood 防护

SYN Flood 是最经典的 DDoS 攻击：攻击者大量发送 TCP SYN 包，但不完成三次握手，把服务器的半连接队列占满，正常用户连不上。

传统防御靠 syncookies（有性能开销）和防火墙限速。用 XDP 可以在报文刚到网卡时就把异常 SYN 丢掉。

五、进阶方向

这个程序只是最基础的版本，生产环境用的 XDP DDoS 防护会复杂得多：

  1. 更精细的检测：不只是按源IP计数，还要结合 TCP 选项、TTL、报文大小分布等特征识别攻击
  2. SYN Cookie：XDP 层面实现 SYN Cookie，不需要占用半连接队列
  3. 多队列支持：现代网卡有多队列，XDP 程序在每个队列上都跑，需要用 per-CPU map 避免锁竞争
  4. offload 到网卡：支持 XDP offload 的智能网卡（如 Netronome/Mellanox）可以把 eBPF 程序卸载到网卡硬件，完全不耗 CPU
  5. 和用户态联动：XDP 只做快速路径的丢弃，复杂分析（如流量画像、攻击溯源）放到用户态程序，通过 BPF map 交换数据

六、小结

eBPF + XDP 把网络数据包的处理能力从内核协议栈下沉到了网卡驱动层，让纯软件方案也能达到接近硬件的性能。除了 DDoS 防护，XDP 还广泛用于：

  • 负载均衡（Facebook 的 Katran，用 XDP 做 L4 LB）
  • 流量镜像和监控
  • 容器网络（Cilium 用 eBPF 替代 iptables 做 Service 转发）
  • 防火墙（替代 iptables/nftables）

学 eBPF 的门槛确实不低，要懂内核网络栈、C 语言、BPF 指令集，但一旦掌握，相当于拿到了内核编程的”超能力”。
