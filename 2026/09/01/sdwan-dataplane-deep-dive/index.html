SD-WAN 数据面深度解析——从 Overlay 隧道到智能选路

最近在啃 SD-WAN 的数据面实现，把 Underlay 和 Overlay 的关系、隧道封装、选路算法这些东西理了一遍，记录一下。

一、Underlay 和 Overlay 到底是什么

SD-WAN 的核心思想就是把控制面和数据面分离，把物理网络和逻辑网络分离。

  • Underlay（ underlay 网络）：就是底层物理网络，运营商的 MPLS 专线、互联网宽带、5G 链路，这些都属于 Underlay。它只负责 IP 连通性，不管你跑的是什么业务。
  • Overlay（叠加网络）：在 Underlay 之上建的逻辑隧道网络，CPE 之间通过隧道封装，把业务报文封装在 Underlay 的 IP 报文里传输。对业务来说，它看到的是一个逻辑上的全互联网络，完全感知不到底层走的是哪条链路。

打个比方：Underlay 是公路系统，Overlay 是在公路上跑的物流专线。货物（业务报文）装进集装箱（隧道封装），不管下面走的是高速还是国道，到了目的地再拆箱。

二、隧道封装协议对比

SD-WAN 常用的隧道协议有三种，各有取舍：

2.1 GRE（Generic Routing Encapsulation）

最简单的封装，直接在原始 IP 包外面再加一层 IP 头 + GRE 头。

优点：简单、开销小、支持组播。
缺点：没有加密，只能在可信的 Underlay 上用（比如 MPLS 专线）。如果走互联网，必须配合 IPSec 加密。

2.2 IPSec（IP Security）

严格来说 IPSec 不是隧道协议，是加密协议。SD-WAN 里通常用 IPSec Tunnel Mode，它会对整个原始 IP 包加密并封装。

优点：加密 + 认证，安全性最高。
缺点：开销大（封装开销约 50-60 字节），建立隧道慢（IKE 协商），不支持组播。

2.3 VXLAN（Virtual Extensible LAN）

数据中心里用得最多，SD-WAN 厂商也开始用。VXLAN 用 UDP 封装，外层是 UDP + VXLAN 头（24 位 VNI）。

优点：支持大二层、VNI 数量多（1600万）、UDP 封装可以做 ECMP 负载分担。
缺点：本身不加密，需要配合 IPSec 或 DTLS；MTU 问题更严重（封装了整个以太网帧）。

实际选型

主流 SD-WAN 厂商的做法是混合使用：

  • 走 MPLS 专线的隧道：用 GRE（专线本身可信，不需要加密，开销小）
  • 走互联网的隧道：用 IPSec 或 GRE over IPSec（必须加密）
  • 需要大二层延伸的场景：用 VXLAN over IPSec

三、MTU 和 MSS 问题——最容易踩的坑

隧道封装会增加额外的报文头，这就带来了 MTU 问题。

假设 Underlay 的 MTU 是 1500：

封装方式 额外开销 有效 MTU
GRE 24B 1476
IPSec Tunnel ~58B 1442
VXLAN 50B 1450

如果业务报文大小是 1500，经过隧道封装后变成 1550+，超过了 Underlay 的 MTU，会发生什么？

如果设置了 DF 位（Don’t Fragment）：报文被丢弃，设备回 ICMP Fragmentation Needed。但很多防火墙会拦 ICMP，导致黑洞——小报文能通，大报文传着传着就断了。

如果没设 DF 位：报文被分片，到了对端再重组。分片会导致性能下降，而且有些设备（特别是状态防火墙）处理分片有问题。

  1. TCP MSS 钳制（MSS Clamping）：
    在 TCP 三次握手时，把 SYN 包里的 MSS 值改小，让对端发送的 TCP 段不超过隧道 MTU。

MSS = MTU - 40（IP头20 + TCP头20），所以 MTU 1400 对应 MSS 1360。

  1. PMTUD（Path MTU Discovery）：靠 ICMP 自动探测，但前提是 ICMP 不被拦。生产环境里不太靠谱，一般还是手动配 MSS。

四、智能选路——SD-WAN 的核心价值

传统路由只看目标地址和路由度量（跳数、带宽），SD-WAN 的智能选路看的是实时网络质量和业务 SLA 要求。

4.1 链路质量探测

CPE 之间会持续发送探测报文（类似 BFD，但更轻量），测量三个指标：

  • 延迟（Latency）：单向或往返延迟
  • 抖动（Jitter）：延迟的变化量
  • 丢包率（Packet Loss）：探测报文的丢失比例

探测报文通常用 UDP 或 ICMP，间隔 100ms-1s，在每条隧道上都跑。

4.2 业务识别

SD-WAN 要知道每个报文属于什么业务，才能做针对性选路。识别方式有几种：

  1. 基于五元组：源/目的 IP、端口、协议。最简单，但不够精细。
  2. 基于 DPI（深度包检测）：识别应用层协议，比如识别出这是 Zoom 视频会议、这是 Salesforce 流量。
  3. 基于域名/URL：通过 DNS 嗅探或 SNI 识别。
  4. 基于 DSCP 标记：信任上游设备打的标记。

4.3 选路算法

选路的本质是一个多目标优化问题：给每条链路打分，选分数最高的。

不同业务的权重不一样：

业务类型 延迟权重 抖动权重 丢包权重 成本权重
语音/视频 高 极高 高 低
实时交易 极高 高 高 低
文件传输 低 低 中 高
网页浏览 中 低 中 中

举个例子：一条 MPLS 专线延迟 20ms、丢包 0.1%、成本高；一条互联网宽带延迟 40ms、丢包 1%、成本低。

  • 语音会议走 MPLS（质量优先）
  • 软件更新走互联网（成本优先）
  • 如果 MPLS 丢包突然升到 5%，语音自动切到互联网（SLA 违约触发切换）

4.4 切换机制

选路不是一成不变的，当链路质量变化时要切换。但切换不能太频繁，否则会导致业务振荡。

常用的机制：

  • 滞后阈值（Hysteresis）：只有当新链路比当前链路好超过一定阈值才切，避免来回跳。
  • 保持时间（Hold Time）：切换后至少保持 N 秒，期间不再切换。
  • 平滑切换：先在新链路上发探测，确认通了再切业务，有些厂商还做了双发选收（同时在两条链路上发，对端选先到的）。

五、QoS 和流量整形

智能选路解决的是”走哪条路”的问题，QoS 解决的是”路上堵车了谁先走”的问题。

关键技术点：

  1. HQoS（分层 QoS）：先按业务分队列，再按用户/站点分队列，适合多租户场景。
  2. WRED（加权随机早期检测）：队列快满的时候随机丢包，避免全局同步（TCP 同时降速又同时提速）。
  3. 流量整形（Traffic Shaping）：把输出速率限制在承诺带宽以内，避免突发流量被运营商丢弃。整形是”缓存后均匀发送”，策略是”直接丢弃”，整形会增加延迟但更平滑。

六、总结

SD-WAN 数据面的核心就三件事：

  1. 封装：用隧道把业务包封起来，Overlay 跑在 Underlay 上
  2. 选路：根据实时质量和业务 SLA 智能选择链路
  3. 保障：用 QoS 确保关键业务在拥塞时也能跑

理解了这三层，再看任何厂商的 SD-WAN 方案，本质都是在这三件事上做不同的实现和优化。下一篇准备写控制面，SD-WAN 的控制器是怎么把策略下发到成千上万个 CPE 的。
